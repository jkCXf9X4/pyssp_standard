# DEC-IMP028-R1-001: Reproducible Archive Builds

- **Status:** Active
- **Date:** 2026-06-10
- **Context:** Build output (FMU archives, SSP archives, XML documents) must be byte-identical when given identical specification files and the same tool version. Without deterministic timestamps, sorted entry ordering, and fixed compression parameters, each build produces a different archive — preventing reliable content-addressed caching, CI comparison, and diff-based review of generated artifacts.

- **Decision:**
  - Adopt `FMI_EPOCH` (2000-01-01 00:00:00) as the canonical zero-timestamp default for all archive entries, replacing filesystem mtime-based timestamps.
  - Use `sorted()` for ZIP entry ordering to ensure consistent iteration order.
  - Use `ZIP_DEFLATED` compression consistently.
  - Thread `fixed_timestamp` through `ArchiveRuntime` and `DirectoryRuntime` so both modes use the same value.
  - XML `generationDateAndTime` is NOT auto-injected during document creation; it remains `None` (absent from serialized XML) unless explicitly set via `set_generation_date_and_time()`.
  - Future additions that introduce timestamp-like output must use the same `fixed_timestamp`-style control pattern.

- **Reproducibility Scope (in scope):**
  - Same specification files + same tool version → byte-identical archives.
  - FMU archive creation (`FMU.create()`).
  - SSP archive creation (`SSP.__init__(mode="w")`).
  - SSP packaging (`FMU.package_as_ssp()`).
  - XML document creation (`mode="w"` for SSD, SSV, SSB, SSM, SRMD, ModelDescription).

- **Out of scope (not required):**
  - Archive unpacking determinism (unpack-to-directory reproducibility).
  - Directory mode determinism (filesystem mtime varies).
  - Cross-version reproducibility (different tool versions may produce different output).
  - Full byte-for-byte round-trip across read-modify-write cycles (lexical details may vary).

- **Non-Determinism Source Register:**
  - ND-001: ZIP entry timestamps (mtime) — fixed by `FMI_EPOCH`.
  - ND-002: ZIP entry ordering — fixed by `sorted()`.
  - ND-003: ZIP compression defaults — fixed by explicit `ZIP_DEFLATED`.
  - ND-004: Missing `generationDateAndTime` in XML — fixed by guardrail tests.
  - ND-005: Filesystem mtime in directory mode — out of scope.
  - ND-006: XML attribute order — out of scope (serializer choice).
  - ND-007: XML namespace prefix spelling — out of scope (serializer choice).
  - ND-008: XML indentation/whitespace — normalized by `ET.indent()` but may differ across ET versions.

- **Consequences:**
  - All archive creation paths now produce deterministic output by default.
  - XML documents created without calling `set_generation_date_and_time()` lack the `generationDateAndTime` attribute (standards-compliant; attribute is optional).
  - Five acceptance criteria (AC-DET-001 through AC-DET-005) guardrail against regression.
  - Decision record and traceability map updated.
